## 📖 프로젝트 소개

**무거운 13 (Heavy 13)**은 7명의 플레이어가 숫자가 적힌 바위 카드와 색깔 칩을 동시에 제출하고, 단계별 공개와 우선순위 정렬 및 패스(역순 후배치) 심리전을 거쳐 3개의 짐꾼 받침대(빨강, 초록, 파랑) 위에 돌을 쌓아 올리는 웹 보드게임입니다.

별도의 백엔드 게임 서버나 데이터베이스(No-DB) 없이 **브라우저 간 WebRTC P2P 직접 통신**과 **상황 인식형 휴리스틱 AI 봇**을 결합하여, 정적 웹 호스팅(Cloudflare Pages)만으로 1인 솔로 플레이부터 7인 실시간 멀티플레이까지 모바일과 데스크톱 어디서든 즉시 즐길 수 있도록 구현했습니다.

## ✨ 주요 기능

* **No-DB 브라우저 간 WebRTC P2P 멀티플레이:**
  * PeerJS 기반 Host-Authoritative Star 토폴로지를 적용하여 방장(Host) 브라우저가 단일 게임 상태 권한을 갖고 참가자(Guest)들과 실시간 상태를 동기화합니다.
  * 치팅 방지를 위해 동시 선택 단계에서는 타인의 미공개 패를 완전히 마스킹하고, 각 참가자에게는 본인의 손패만 전송합니다.
* **상황 인식형 로컬 AI 봇 (1~7인 유연한 플레이):**
  * 7명의 슬롯 중 실제 접속자가 없는 빈자리는 방장 브라우저 내에서 동작하는 휴리스틱 AI 봇이 자동으로 채웁니다.
  * 받침대별 현재 합계, 쌓인 돌의 개수(벌점 손절 계산), 남은 배치 대기열을 분석해 칩·카드 조합 및 패스(LIFO) 여부를 판단하며, 게임 도중 참가자 연결이 끊기더라도 즉시 AI 봇으로 전환되어 완주됩니다.
* **직관적인 3색 짐꾼 받침대 적층 UI & 제출자 확인:**
  * 빨강(RED), 초록(GREEN), 파랑(BLUE) 3개의 받침대 위에 바위 큐브가 2열 그리드로 아래에서 위로 쌓이는 시각적 보드를 제공합니다.
  * 쌓인 돌 타일을 클릭(터치)하거나 마우스를 올리면 해당 돌을 올린 플레이어의 닉네임과 사용 칩 정보를 툴팁으로 확인할 수 있습니다.
* **모바일 퍼스트(Mobile-First) 반응형 UI & 내장 룰북 모달:**
  * 모바일 세로 뷰포트(`100dvh` 및 Safe-Area 대응)에서 스크롤 없이 한 화면에 플레이할 수 있도록 2줄 카드형 7인 참가자 현황판과 하단 엄지손가락 전용 컨트롤 독을 제공합니다.
  * 로비 및 게임 도중 언제든지 상단 `?` 버튼을 눌러 상세 게임 규칙을 확인할 수 있습니다.
* **Web Audio API 실시간 합성 효과음:**
  * 외부 오디오 파일 없이 브라우저 내장 Web Audio API로 돌 안착음, 칩 선택음, 패스음, 13 폭발 경고음을 실시간으로 합성하며 상단 헤더에서 음소거를 제어할 수 있습니다.
* **3개 국어 다국어 지원 (i18n) & SHA-256 비밀번호 게이트:**
  * 한국어(`ko`), 영어(`en`), 일본어(`ja`) UI 실시간 전환을 지원하며, 각 플레이어가 자신의 브라우저에서 선택한 언어로 게임 로그와 룰북을 이용할 수 있습니다.
  * Web Crypto API(`SHA-256`) 단방향 해시 검증을 통해 지정된 비밀번호를 입력한 지인만 로비 및 초대 방에 입장할 수 있습니다.

## 🎮 게임 규칙 (원작 메커니즘 + 하우스 룰 반영)

1. **인원 및 라운드:** 총 7인 고정, 전반부(1~7라운드)와 후반부(8~14라운드)로 구성된 총 **14라운드**를 진행합니다.
2. **초기 지급 자원:** 시작 시 전원에게 바위 카드 7장(`0`~`6`)과 색깔 칩 7개(`RED` x2, `GREEN` x2, `BLUE` x2, `RAINBOW` x1)가 지급됩니다.
3. **라운드 진행 단계 (동시 제출 → 순차 공개):**
   * **동시 선택:** 7명 전원이 동시에 색깔 칩 1개와 바위 카드 1장을 비밀리에 제출합니다.
   * **단계별 공개:** 전원 제출 완료 후 **색깔 칩을 먼저 일제히 공개**하고, 이어서 **바위 카드 숫자를 공개**합니다.
4. **큐브 배치 우선순위 및 패스(Pass) 규칙:**
   * **배치 순서:** ① `RAINBOW` 칩 제출자 최우선 → ② 바위 카드 숫자가 높은 순서(`6` → `0`) → ③ 동순위 시 현재 **선 플레이어(👑)** 기준 시계 방향 순으로 배치합니다.
   * **패스(라운드당 1회):** 자신의 배치 차례에 1회 패스를 선언할 수 있습니다. 패스한 플레이어들은 일반 배치가 모두 끝난 뒤, **패스를 선언한 순서의 역순(LIFO: 마지막에 패스한 사람부터)**으로 큐브를 배치합니다.
5. **13 이상 폭발 정산 및 선 플레이어 승계:**
   * 큐브를 올려 특정 받침대의 숫자 합이 **13 이상**이 되면, **방금 올린 큐브를 제외한 기존 큐브들이 모두 수거**되며 그 **수거된 큐브의 개수만큼 벌점**을 받습니다. (방금 올린 큐브 1개만 해당 받침대에 남습니다.)
   * 해당 라운드에서 **가장 마지막으로 벌점을 받은 플레이어**가 다음 라운드의 선 플레이어가 됩니다.
6. **중간 정산 (7라운드 종료 후):**
   * 8라운드 시작 시 모든 플레이어의 **손패(카드·칩)만 새로 재지급**되며, **기존 3개 받침대에 쌓여 있던 돌과 합계는 그대로 유지**됩니다.
7. **승패 결정:** 14라운드 종료 후 누적 벌점이 가장 높은 최하위 2명이 탈락합니다.

## 🛠 기술 스택 (Tech Stack)

* **Frontend:** React 19, TypeScript (Strict Mode), Vite
* **Styling & Icons:** Tailwind CSS, Lucide React
* **State Management:** Zustand
* **Networking:** PeerJS (WebRTC `RTCDataChannel`)
* **Audio & Security:** Browser Native Web Audio API, Web Crypto API (`SHA-256`)
* **Deployment:** Cloudflare Pages (Static Hosting)

```text
src/

├── types/            # 라운드 페이즈, 제출/배치 큐, P2P 프로토콜, Sanitized 뷰 모델 타입 정의
└── utils/            # Web Audio 효과음 합성기 및 SHA-256 해시 검증 유틸리티
```

## 🚀 로컬 실행 및 배포 방법

### 1. 의존성 설치 및 개발 서버 실행
```bash
npm install
npm run dev
```

### 2. 입장 비밀번호 해시 설정 (`.env`)
원하는 비밀번호를 SHA-256 해시로 변환한 뒤 프로젝트 루트의 `.env` 파일(또는 Cloudflare Pages 환경 변수)에 등록합니다.

```bash
# 비밀번호 SHA-256 해시 생성 예시
node -e "console.log(require('crypto').createHash('sha256').update('your-password').digest('hex'))"
```

```env
VITE_APP_PASSCODE_HASH=생성된_64자리_SHA256_해시값
```

### 3. 프로덕션 빌드 (Cloudflare Pages)
```bash
npm run build
```
* **Build command:** `npm run build`
* **Build output directory:** `dist`
